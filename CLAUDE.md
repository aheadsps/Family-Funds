# Поток (Family-Funds)

Семейный бюджет как PWA: чистый JS без сборки и без npm-зависимостей в самом приложении, данные в Firebase (Auth + Firestore), хостинг на GitHub Pages. Интерфейс и тексты на русском, на «вы».

## Файлы
- `index.html`: разметка и все стили внутри. `app.js`: весь интерфейс и расчёты (около 1900 строк, плотный стиль). `fb.js`: слой Firebase. `icons.js`: иконки Lucide. `sw.js`: офлайн-кэш.
- `firestore.rules`: правила доступа. `tests/rules/`: тесты правил на эмуляторе. `firebase.json`: нужен только для тестов.
- `firebase-config.js`: публичные ключи проекта, секретов в репозитории нет.

## Как проверять
- Локально: `python3 -m http.server` в корне, открыть в браузере. Параметр `?debug` в адресе даёт `window.__potok` для отладки расчётов.
- Расчёты: `node --test tests/calc/calc.test.mjs` (без зависимостей, Node 20+). Запускать после правок `distribute`, `monthReq`, `dlPlan`, `simulate`, `etaSim`.
- Правила Firestore: `cd tests/rules && npm install && npm test` (нужны Node и Java). Запускать после любой правки `firestore.rules`.
- Линтера в репозитории нет. При аудите использовали ESLint и html-validate вне репозитория. Намеренно оставлены: неразрывный пробел в регулярке `parseAmt` и пустые `catch`.

## Как задаётся фонд (окно фонда, `fundShape` и `fundFields` в `app.js`)
Три правила «как фонд получает деньги»: платёж в месяц, % с дохода, весь остаток. Два тумблера: «Это долг» и «Накопить сумму». Хранится в базе как раньше (`kind`: monthly, percent, rest, goal, debt, reward), без миграции:
- без тумблеров: monthly, percent, rest;
- «Накопить сумму»: goal. Месячное правило пишет в `cap`, процентное в `pct`, остаток без правила;
- «Это долг»: debt. Месячное правило пишет в `minPay`, процентное в `pct`, остаток с `minPay` 0;
- оба тумблера: goal с `isDebt` (долг, который закрывается одним платежом, например рассрочка у приставов без ставки). Деньги копятся в фонде, потом платёж записывается из фонда (`pay-lump`).
- Фонд наград (`reward`) есть у каждой семьи: `ensureReward` создаёт его сам с id `reward` и 10%, удалить нельзя (UI и правила Firestore), можно поставить 0%.
Правило «процент» у цели и долга (`pctRate`): берут свой процент с каждого дохода, пока не накопят или не погасят, и не получают деньги сверх плана по очереди.

## Как делятся доходы (`distribute` в `app.js`)
1. Налог и процентные фонды берут долю от каждого поступления.
2. Обязательное на месяц (`monthReq`) по уровням: **жизнь** (платежи в месяц) → **минимальные платежи по долгам** → **планы** (добавка ради срока у долгов и целей, взносы в цели с лимитом; `reqParts`). Следующий уровень получает деньги, только когда предыдущий закрыт полностью; внутри уровня нехватка делится пропорционально. Очередь здесь не участвует. Так сроки по долгам и целям никогда не отнимают деньги у еды и жилья.
3. Сверх обязательного: награды (процент от остатка), затем долги и цели по очереди фондов, остаток в фонд «остаток» (rest) или «без фонда».
Просроченный срок у долга или цели обязательное не раздувает: фонд ведёт себя как без срока. План по сроку для долга со ставкой считается аннуитетом (`dlPlan`), без ставки равными долями.
Платёж по долгу считается оплаченным, когда деньги внесены в банк (отметка «Внёс» из «Ресурсов» или записанный платёж по долгу, `debtPaidM`), а не когда они отложены в фонд при доходе. Для фондов «платёж в месяц» оплатой считается записанная трата. Тексты подсказок и справки в интерфейсе должны описывать именно эту модель.

## Изменение и удаление дохода
- Удаление дохода идёт через окно с предпросмотром (`openDeleteIncome`): сколько уйдёт из каждого фонда, какие фонды уйдут в минус. Удаление только после подтверждения, деньги просто уходят из фондов, минус у «платежа в месяц» закроет следующий доход.
- Изменение суммы (`reallocIncome`) не раскладывает доход заново: процентные фонды пересчитываются от новой суммы, добавка раскладывается как обычный доход, нехватка снимается в обратном порядке раскладки (без фонда, накопления, награды пропорционально доходу, цели и долги снизу очереди, обязательное последним и пропорционально). Окно показывает «Что изменится» (`allocEffect`, `effectRows`).

## «Ещё нужно заработать» (главная) и реальность сроков
- Главная цифра это жизнь и минимальные платежи по долгам (`coreNet`/`coreGross`) с учётом налога. Планы по срокам (`planNet`/`planGross`) показаны отдельной строкой.
- `planCheck` проверяет планы по обычному доходу (`usualIncome`): сколько остаётся на планы после жизни, минимальных платежей и наград (`free`), сколько просят сроки (`ask`), и когда каждый фонд со сроком закроется на самом деле (`etaSim`). Если не сходится, главная, подсказка «Сроки не сходятся с доходом», окно «Из чего складывается» (`openNeedWhy`) и окно фонда (под полем «Срок») говорят об этом и называют реальную дату.
- Бюджет на долги (`debtBudget`, вкладка «Долги») считается из дохода: минимальные платежи плюс свободные деньги, а не из того, что просят сроки.
- Если жалуются на «странную» сумму, сначала смотрите сроки у фондов, а не ищите задвоение: его нет.

## Вкладка «Фонды»
Фонды показаны по уровням (`FTIERS`): с каждого дохода, жизнь, долги и цели (очередь), награды, остаток. Перетаскивать можно только в очереди долгов и целей (порядок важен только там); `reorderGroup` меняет порядок внутри группы, не трогая остальные фонды.

## Отметка «Уже оплачено»
В «Ближайших платежах» рядом с «Оплатил» есть «Уже оплачено»: запись `paidmark` (fundId, amount, month) без траты. Для платежа в месяц она закрывает обязательство месяца (`stats` добавляет сумму в `spentM`, баланс фонда не трогается), для долга снимает ожидание платежа в «Ресурсах» (`debtPending`). В истории видна «Отмечен оплаченным», её можно удалить, и платёж снова появится.

## Ресурсы (карты и наличные)
- В «Где хранятся фонды» показаны все фонды, включая долги, цели и накопления; карту можно выбрать и снять.
- Долгу тоже можно назначить карту (`accountId`): деньги, отложенные на платёж, ждут на ней до «Внёс» (`reconcile`, `onAcc`), и подсказка вносит платёж прямо с этой карты. Долг без карты работает как раньше: платёж с любой карты, где есть лишние деньги.

## Правила работы
- Правила Firestore сами не деплоятся: после слияния владелец вставляет `firestore.rules` в консоль Firebase (Firestore Database, Rules, Publish). Скажите об этом, если правила менялись.
- Менялся список файлов оболочки (`SHELL` в `sw.js`) или нужно сбросить кэш у пользователей: поднять версию `CACHE` в `sw.js`.
- Горизонтальный вид телефона (низкий экран, `(orientation:landscape) and (max-height:500px)`): вкладки уходят в боковую панель, шапка тонкая. Правила в конце стилей `index.html`, `moveTabInd` в `app.js` знает про оба положения (`RAIL`). Отступы безопасной зоны идут через `--sat/--sar/--sab/--sal`. Проверять сквозными скриншотами в 844×390 и 932×430.
- Обновления: сайт отдаётся из офлайн-кэша, поэтому телефон видит новую версию только при следующем запуске. `sw.js` сравнивает ETag и сообщает странице `{type:'update'}`, `app.js` показывает «Вышла новая версия, Обновить»; в меню есть «Обновить приложение» (`refresh-app`: сбрасывает кэш и сервис-воркер, данные не трогает). Когда жалоба «не вижу исправление», сначала проверяйте, что телефон не на старой версии.
- Зум страницы отключён намеренно (`user-scalable=no`). Не включать.
- Шрифты лежат в репозитории (Unbounded, Golos Text). Внешние сервисы шрифтов не подключать.
- Расчёты (`stats`, `distribute`) быстрые: 20 000 записей считаются меньше 3 мс. Кэшировать их без замеров не нужно.
